# Windows-view check: let_there_be_flight

Base: `main` (`6d7c1b7`, which is tag `v0.3.18` plus 18 commits). Review by Grok (read-only), checked by Claude; the four changes it found are fixed (see below). That first review was made against `v0.3.18`. The check was run again against `main` on 2026-10-14, after the rebase, and the table below is the result of that run.

Method: for every shared file the branch changes (outside `macos/`), compare the Windows view with `main`, then for each listed file

`diff -u <(git show main:<f> | unifdef -U__APPLE__ -t) <(git show HEAD:<f> | unifdef -U__APPLE__ -t)`

and the full `git diff main HEAD -- <f>` for the `#ifdef __APPLE__` context. Line numbers below are the branch (`HEAD`) unless noted.

`unifdef -U__APPLE__` drops `#ifdef __APPLE__` / `#if defined(__APPLE__)` branches and keeps the `#else`. A Windows macro that expands to the original expression is NO-OP even though the source text differs before preprocessing.

Files compared: the 43 files `git diff --name-only main HEAD -- . ':!macos'` lists. Windows view identical to `main` (no row below): `src/red4ext/Engine/RTTIRegistrar.cpp`, `Extensions/InkMaskWidget.cpp`, `Extensions/InkWidget.cpp`, `Hooks/AreaSpeedLimiter.cpp`, `Hooks/vehicleTPPCameraComponent_GetLocationFromOffset.cpp`, `Hooks/vehicleTPPCameraComponent_GetYaw.cpp`, `Hooks/vehicleUnk580_UpdateTireParameters.cpp`, `Utils/Utils.cpp`. The other 35 differ and have rows below. Four of them differ only by whitespace, a final newline or one blank line: `Hooks/GetMatrixFromOrientation.hpp`, `LoadResRef.hpp`, `Hooks/vehicleTPPCameraComponent_UpdatePitch.cpp` and `stdafx.hpp`. The `RED4EXT_ASSERT_OFFSET` redefinition in `stdafx.hpp` is inside `#ifdef __APPLE__` (`stdafx.hpp:24-33`) and is absent from the Windows view.

No Windows-view hunk changes a `RED4EXT_ASSERT_OFFSET(...)` constant. Those lines show up only as unchanged diff context (`Flight/Component.hpp:126-128`, `FlightConfiguration.hpp:72-74`, `FlightSystem.hpp:81-83`, `FlightThruster.hpp:36-38`).

## Rebase onto main

`main` has 18 commits that `v0.3.18` does not (guards against corrupt or null game data, the FlightHUD gate, the cinematic camera fix, `FindGround` gating, docs and tooling). Four files had merge conflicts where upstream's new guards met the Mac code: `Extensions/MeshComponent.cpp`, `Extensions/VehicleObject.cpp`, `FlightConfiguration.cpp` and `Hooks/Entity_InitializeComponents.cpp`. In all four the Windows view equals `main` apart from the rewrites in the table (macros, a comment, a final newline). Upstream's new guards (`Utils::LooksLikeDynArray` checks, null checks, `LTBF_WARN_ONCE` calls, the `IsFlightHudEnabled` gate) appear as the same text in both Windows views.

## Fixed after the first review

The first review (against `v0.3.18`) found four hunks that changed the Windows view: the function-local registrar list in `Engine/RTTIRegistrar.cpp`, and in
`RuntimeProperties.cpp` a null-class skip, a null check around `CProperty::Create` and reworded log lines. All four are now under
`#ifdef __APPLE__` with the original code in the `#else`; the Windows view of both files is identical to `main` except the
`LTBF_REGISTER_COMPOSITE_TYPE` macro, which expands to the original `rtti->RegisterType(...)` call on Windows.

Re-run the check:

```
for f in $(git diff --name-only main HEAD -- . ':!macos'); do
  diff -q <(git show main:$f 2>/dev/null | unifdef -U__APPLE__ -t) <(git show HEAD:$f | unifdef -U__APPLE__ -t) >/dev/null || echo "$f"
done
```
